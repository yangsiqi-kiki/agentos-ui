## 适用场景

当你需要从 Figma 新增组件、调整已有组件，或为组件补齐 Storybook 时，优先让
AI Agent 执行完整流程。你负责提供设计与需求、确认结果；Agent 负责读取规则、
调用 Figma MCP、修改代码并完成校验。

## Agent 必须遵守的实现约定

### Token 与样式

- 优先使用语义 token，不直接使用 Base 色阶表达业务语义。
- 颜色、字号、间距和圆角均使用 `agentos` token class。
- 使用 `cva` 管理 variant，使用 `cn()` 合并 `className`。
- 组件使用 `forwardRef` 与显式 props，并保持单文件单组件。

### 图标

- 默认使用 `lucide-react`，Lucide 无对应图标或设计明确为 Tabler 时使用
  `@tabler/icons-react`。
- 禁止手写内联 SVG 或用 `<img>` 充当图标。
- 图标尺寸由容器 class 控制，颜色通过 `currentColor` 继承。
- 装饰性图标添加 `aria-hidden="true"`；可交互图标所在按钮提供
  `aria-label`。

### 文案

- 组件默认文案使用英文，便于宿主覆盖和回退。
- label、placeholder、`aria-label`、title、空态等用户可见文案必须通过
  props 覆盖。
- 组件库不内置 i18n 运行时，本地化文案由宿主传入。

## Agent 必须补齐的 Storybook 内容

每个新增组件需要在同名 PascalCase 文件夹内同步提供以下三部分：

1. `stories/<ComponentName>/<ComponentName>.stories.tsx`：使用 CSF 定义变体、状态与交互示例；引用组件源码用 `../../../src/...`。
2. `stories/<ComponentName>/<ComponentName>.mdx`：使用 `ComponentMeta`、`Controls` 和
   `TokenUsage` 编写中文说明书；引用共享布局用 `../docs/_layout`；Atoms、Molecules、Organisms 使用 `Canvas`
   展示示例，Layouts、Pages 使用 `StoryLink` 链接到独立 story。
3. `docs/component-meta.anti-pattern.ts`：登记中文名、描述、分类、Figma
   链接和常用 token。

Story 的 `title` 按组件层级命名，例如 `Atoms/Button`。可枚举 props 使用
`argTypes` 和 `select` 控件；除单一状态 story 外，应提供一个聚合 story
集中展示主要变体。MDX 使用 `<Meta of={Stories} />` 关联 story，不再添加
`tags: ['autodocs']`。Layouts 与 Pages 不在 Docs 中内嵌全幅界面，避免受到
Docs 容器宽度限制而变形。

## Agent 必须执行的校验

```bash
pnpm --filter @agentos/design-system lint
pnpm --filter @agentos/design-system typecheck
pnpm --filter @agentos/design-system storybook
```

## 你的验收清单

- Storybook 中的视觉结果与 Figma 一致
- 主要尺寸、状态、变体与交互都可在 story 中查看
- 组件 API 符合实际使用场景，没有写死业务文案
- MDX 包含概述、示例、用法、Props 与相关 Token
- Agent 已汇报 Figma 变量到 AgentOS token 的映射
- lint、typecheck 和 Storybook 构建均已通过
- Agent 已明确列出图标、交互或响应式等仍需人工确认的差异
