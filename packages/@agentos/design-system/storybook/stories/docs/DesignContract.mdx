## 这是什么

`DESIGN.md` 面向设计方、设计工程与前端查阅。核心是三列对照：

<DocTable
  columns={['列', '含义', '谁用']}
  rows={[
    [<strong>Figma 路径</strong>, 'Figma Variables 层级名', '设计师绑定变量'],
    [
      <strong>CSS 变量</strong>,
      <>
        运行时 <code>--agentos-*</code>
      </>,
      '前端 / 样式',
    ],
    [
      <strong>Tailwind</strong>,
      <>
        <code>text-agentos-*</code> 等 class
      </>,
      '前端实现',
    ],
  ]}
/>

设计师在 Figma 中绑定变量时使用 **Figma 路径**；前端实现时映射到 **CSS 变量**或 **Tailwind** class。组件禁止硬编码色值。

### 语义分组

- **Neutral**：文本、背景、边框、填充等中性语义
- **Brand**：主色、链接、成功 / 警告 / 错误
- **Base**：色阶原语（如 Blue 50–900），供语义色引用
- **MaskBase / MaskSenior**：遮罩透明度

### 开发时怎么选 token

1. **优先语义色**：按钮主色用 `bg-agentos-brand-primary-color-primary`，不要直接写 `bg-agentos-base-blue-500`。
2. **文本层级**：正文 / 次要 / 占位分别用 `colorText` / `colorTextSecondary` / `colorTextPlaceholder`。
3. **完整清单**：日常查阅本 Storybook 的 Tokens 页；需要全量对照时打开包内 `docs/token-reference.md`，或使用下方下载包中的附录。

### 在本仓库中如何重新生成

源文件在 `src/tokens/source/*.json`（Figma 导出）。修改后运行：

```bash
pnpm --filter @agentos/design-system build:tokens
```

会重新生成 `tokens.css`、`generated-theme.ts`、`DESIGN.md` 与 `docs/token-reference.md`。

## 如何在你的项目中使用

外部 React / Next.js 项目可按下列顺序接入：

1. **下载**上方 zip，把 `DESIGN.md`（及附录）放入项目。
2. **复制** [组件生成 Skill](?path=/docs/overview-组件生成-skill--docs) 全文到 `.agents/skills/component-creator/SKILL.md`。
3. **确保** Cursor 已连接 Figma MCP（若从设计稿生成）。
4. **向 Agent 发送**下方提示词模板，替换 `<...>` 占位内容。

Skill 会先探测项目（是否有 Storybook / Tailwind / shadcn），缺依赖时会初始化基建，再按 `DESIGN.md` 映射 token 并生成组件。

## 实现要求

1. 先完成项目探测（框架、Tailwind、shadcn、Storybook、DESIGN.md）。
2. 若缺 Tailwind / shadcn，按 skill 脚手架步骤安装并初始化，再依据 DESIGN.md 写入 token。
3. 有 Figma 时通过 MCP 获取 design context、截图和变量定义，不要根据截图猜测 token。
4. 对照 DESIGN.md（及附录）完成 Figma Variables 到项目 token 的映射。
5. 优先复用已有 primitive；图标使用 Lucide 或 Tabler，禁止手写内联 SVG。
6. 仅当项目已有 Storybook 时补齐 CSF story（及项目既有的 MDX 约定）。
7. 所有默认文案使用英文且可通过 props 覆盖，不在组件库中引入 i18n 运行时。
8. 保留工作区中与本任务无关的已有改动。
